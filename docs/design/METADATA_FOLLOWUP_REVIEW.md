## Source findings and tradeoffs

`BrowserScreen` currently starts `syncLibrary` on location/adult-filter changes even before its loading-state guard. `HomeViewModel.syncLibraryData` can call `ensureAliases`, which constructs a VOD route index and writes identity aliases in one database transaction. That is a plausible startup contributor. It is not established that this work caused the complete reported delay; source inspection is not device timing. Deferral must preserve durable old favorite links and progress rather than simply dropping reconciliation. API-only global results may become available when their destination opens rather than being resolved during initial Live TV startup.

The root calls the shared action helper with a fixed height and minimum width, explaining unequal widths instead of browser-sized tiles. Details always show Retry and Playlist categories. Lists show Back, Refresh and Playlist categories. The legacy/global context explicitly renders both Mark watched and Mark unwatched/reset, while the separate library context already selects one title from watched state; both paths need consistent behavior.

Info currently suspends its controller timeout and its visibility listener does not dismiss the independent popup when controls hide. The local test deliberately expects indefinite visibility, so PLAY-015 needs a revised assertion after approval. Its new automatic dismissal trades unlimited reading time for the same predictable disappearance as playback controls; the user can reopen Info.

Remote Back makes the extra Back action unnecessary on the intended TV target. Removing routine Refresh leaves automatic freshness plus failure-only retry. The separate Settings channel-list refresh remains available. Root-only Playlist categories reduces repeated controls while keeping a deliberate compatibility route one sidebar activation away. No touch/mobile redesign, general manual-refresh relocation, icon dependency, EPG, player/decoder change or broad memory/startup migration is included.
