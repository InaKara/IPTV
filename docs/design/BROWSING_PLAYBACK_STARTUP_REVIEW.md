## Findings from source and the existing asset

- `HomeViewModel.search` cancels/launches playlist searching and optional cached-library reconciliation for every edit. `HomeScreen` already handles the keyboard Search action, but currently that action only closes editing and moves focus.
- `LibraryViewModel.load` sets `preparing=true` while a fresh listing has `loading=false`. `LibraryPane` suppresses the empty message during preparation but renders its spinner only for `loading`. This is a source-supported explanation for blank category pages; actual device timing and the installed version have not been checked.
- Listings are streamed to SQLite, not retained as one provider movie-list object in RAM. UI pages contain at most 60 entries. Parent navigation pages retain rows/details; identity/prepared-alias caches are already bounded to 256 entries. Detail/episode cache accounting is bounded to 20 MiB; this is not a limit on the entire database. Clearing disk movies on a Series visit would discard useful local navigation/search data and cause more downloads. No retained-heap measurement has established the largest current owner.
- Playback owns one ExoPlayer engine and releases it on exit. The user clarifies that output is through a soundbar and additional speakers, with no TV-speaker output, and describes an echoey quality rather than a suspected setup issue. Start with the affected source tracks/channel layout; no setup change is proposed. Source alone does not establish the cause or rule out decoder/output interactions.
- The app uses Media3 1.2.1 native PlayerView, does not explicitly expose its subtitle button, and has no subtitle fields in LibraryEntry/LibraryDetails. The pinned [PlayerControlView source](https://github.com/androidx/media/blob/1.2.1/libraries/ui/src/main/java/androidx/media3/ui/PlayerControlView.java) defaults that button to hidden. A hidden chooser does not establish that no subtitles render: default/forced selection and actual source tracks still matter. [Android track-selection guidance](https://developer.android.com/media/media3/exoplayer/track-selection) states that preparation reveals available tracks. Provider title metadata is insufficient to inventory them.
- Startup uses a 200 dp classic JPEG on black with white text, both in the launch drawable and shared Compose branding. The actual JPEG has a slightly textured cream background: sampled corners range around #E5E4C6. It is not a uniform transparent asset.
