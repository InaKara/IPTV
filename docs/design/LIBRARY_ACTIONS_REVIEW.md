## Interaction and data decisions

- The Play label is always Play. HH:MM moves to the choice dialog when Resume is applicable; retain the saved point until the user chooses Start from beginning. Do not present a meaningless Resume choice for a new, completed, too-short, unknown-duration or known nonseekable item. Actual stream capability is checked again when playback prepares.
- The watched button communicates current status, rather than requiring the user to infer it from an opposite action label. Its accessible action remains Mark watched / Mark unwatched. Keep actual-state reads and lifecycle-safe focus restoration from MD-2.
- Only the heart is icon-only. Its outline/fill conveys saved favorite state without extra text, with accessible state/action naming and the same focus height as Play. It never starts playback.
- The three-control requirement applies to the primary action row, replacing Actions/Restart. Preserve the already approved contextual failure retry and explicit next-episode navigation; do not add automatic playback, a new sidebar destination or a whole-series state operation.
- A season favorite is a shortcut into a collection, not a playable stream or a renamed existing favorite. Additive typed storage may require a small built-in SQLite schema/record extension plus global Favorites routing. Preserve all old data, identities, duplicate occurrences and no-backup storage. Retained season references are user data, independent of the 20 MiB temporary detail cache. Do not derive season identity by display name or invent missing season numbers.
- Resolving a season favorite can load that one series response when needed. Opening VOD's five tiles still performs no metadata/database reconciliation or eager whole-catalog construction. Preserve the ANR correction, bounded result retention and off-main-thread work.
- Verbose logging adds some runtime/log-buffer overhead while enabled. Default Off avoids that ongoing cost. Logging does not turn on broader provider/device probes, bypass deployment permissions or change diagnostics into an information export feature. The current installed workflow uses a debug APK; release startup diagnostics remain disabled under existing guidance.
